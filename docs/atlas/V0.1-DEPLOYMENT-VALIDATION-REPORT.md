# V0.1 Local Deployment and Recovery Validation (WO-024)

Measured by `scripts/v01_closure_sprint.py` against the local Docker Compose
stack and published to `tmp/integration-logs/v01-deployment.json`.

## Proven behaviour

- `docker compose config` validates the documented configuration.
- A clean boot reaches API and dashboard health with all services running.
- A controlled restart of the API and PostgreSQL preserves durable task,
  telemetry and content-addressed storage state.
- Flushing Redis does not destroy canonical truth and the API reconstructs the
  required hot state from PostgreSQL and CAS.
- An isolated secondary data root configured through `HIVE_DATA_ROOT` is honoured
  end to end, including CAS layout creation, on this host.

## Known limitations

- The secondary root is an isolated directory on the same host because no
  physical secondary disk exists in this environment; the documented path and
  configuration semantics are what is proven.
- Redis is explicitly outside canonical backup and recovery.
