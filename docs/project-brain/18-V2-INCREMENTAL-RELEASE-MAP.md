## Cross-release rules
Every release must:
- remain locally deployable;
- preserve user-owned canonical data;
- have explicit upgrade and rollback semantics;
- expose relevant telemetry in Control Center;
- keep experimental providers optional;
- benchmark optimization against quality;
- preserve exact provenance;
- fail closed on authority/security ambiguity;
- leave the prior stable release usable until promotion.

## Planning gap policy
Anything not supported by the frozen source is a NEW CANDIDATE, not retroactively described as frozen. New candidates require classification and evidence before entering the release train.
